# Database migrations

Migrations run in order (by filename). Recorded in `schema_migrations`.

## V7 — Seed projects from config

`V7__seed_projects_from_config.sql` seeds projects and milestones from all `js/config*.js` files.

- **Generated by:** `npm run seed:config` (from repo root: `node packages/api/scripts/generate-config-seed.mjs`).
- **Requires:** At least one org and one user (e.g. from app sign-up). Creates `config-seed-org` and a seed user if none exist.
- **Behavior:** One workspace per config file (e.g. `config`, `config-base`, `config-dsm`); each workspace gets projects and milestones from that file’s `CONFIG.DELIVERABLES`, plus **workflow_definition** and **settings** (start_month, end_month from `CONFIG.TIMELINE`). If the workspace already exists, it is updated with workflow and settings. At the end, all users are added as admins to the seed org. Re-run safe: `ON CONFLICT DO NOTHING` / `DO UPDATE` used where appropriate.

## V8 — Add users to seed org

If you applied V7 before it added users to the seed org, run migrations again; V8 adds every existing user to `config-seed-org` so they see the seeded workspaces. The API also prefers an org that has workspaces when choosing the default org for a user.

## V9 — Backfill workspace workflows

`V9__backfill_workspace_workflows.sql` is generated by the same script and sets `workflow_definition` and `settings` on existing seed workspaces that were created by V7 before workflow/settings were added. Run `npm run migrate`; V9 will run once and backfill so the Timeline tab works.

To regenerate the migration after changing any `js/config*.js`, run from repo root:

```bash
npm run seed:config
# or
node packages/api/scripts/generate-config-seed.mjs
```

Then run migrations as usual: `npm run migrate` (from `packages/api`).
